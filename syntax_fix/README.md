# Починка сломанных файлов декомпиляции

Было **82** файла, которые не компилировал бы ни один компилятор Java.
Стало **8** синтаксически сломанных — плюс **4** файла, которые пропускал
`javalang`, но на которых падает javac. Всего в патче **78 файлов**.

Проверено настоящим `javac` (сборка на Termux): 680 ошибок → 66 после патча,
подробности в `../javac_results/README.md`.

Правки — в `syntax_fixes.zip` (78 файлов). Каждый изменённый файл
приложен как есть, применять поверх `Delta-2_sources.zip`.

## Правила (все — только при подтверждённой валидности)

Ключевой принцип: **каждая правка немедленно проверяется парсером**. Если файл
после правки не стал валидным — правка не применяется. Поэтому регрессий нет:
было 82 сломанных, осталось 8, и ни один ранее валидный файл не тронут.

| правило | что чинит | файлов |
|---|---|---|
| **R7** | неизвестный тип `??` → `var` (если есть инициализатор) или `Object x = null;` | 31 |
| **R10** | порча инлайна константы: `x.getCom.appsflyer…Payload.TYPE java.lang.String()` → `x.getType()` | 13 |
| **R1** | Android-stub `interface X { static { throw new NoClassDefFoundError(); } }` → пустой интерфейс | 9 |
| **R2** | `enum X extends Y` (в Java запрещено) → `public static class X extends Y` | 7 |
| **R11** | `interface` со `static`-блоком (невозможно в Java) → `abstract class` | 5 |
| **R6** | обрыв выражения перед блоком `JADX ERROR` → усечение до корректной границы | 4 |
| **R5** | ключевое слово как имя поля (`public final char char;`) → `char char_;` | 4 |
| **R9** | согласованное переименование обращений (`this.char`, `obj.char`, `default.I(…)`) | 4 |
| **R8** | stub-класс со `static`-блоком, где `throw` не в методе → блок удалён | 1 |
| **R3** | `static final` без инициализатора → `= null` | 1 |

### Примеры

```diff
- public /* synthetic */ interface Activity$ScreenCaptureCallback {
-     static { throw new NoClassDefFoundError(); }
- }
+ public interface ScreenCaptureCallback {
+ }

- public enum a extends b {
+ public static class a extends b {

- p9.c.v(parcel, 1, kVar.getCom.appsflyer.sdk_base.referrer.Payload.TYPE java.lang.String(), false);
+ p9.c.v(parcel, 1, kVar.getType(), false);

- public static final b.c f37448a;
+ public static final b.c f37448a = null;

- ?? r32;
+ Object r32 = null;

- public final char char;
+ public final char char_;
```

## Что осталось (8 файлов) — код потерян безвозвратно

Это не «не смог починить», это места, где JADX **не сохранил** конструкцию:

| файл | причина |
|---|---|
| `pn/a.java` | enum-константы (`None, First, Other;`) остались **без объявления enum** — восстановить можно только по исходному DEX |
| `n0/i4.java` | `static`-блок вложенного интерфейса приклеен к внешнему классу; перенос требует знания исходной структуры |
| `iv/b.java`, `kotlin/collections/h0.java` | поле `default` + его использования в разных формах; полный каскад затрагивает `@Metadata`, который переписывать нельзя |
| `qr/e4.java` | `this.char` в классе, где `char` — и поле, и тип одновременно |
| `fp/m0.java` | обрыв выражения внутри `throw`-блока: обрезать без потери смысла нельзя |
| `Id.java` | поле `class` (ключевое слово) в связке с `@Metadata` |
| `p9.java` | вложенный `javalang`-несовместимый листинг байткода (`SPUT`/`SPUT` с полными именами) |

Каждый из них требует ручного разбора с сверкой по DEX — это отдельная работа
на часы, а не механическая.

## Как воспроизвести

```bash
python3 syntax_fix/fix_syntax.py /tmp/x/out/sources          # отчёт, ничего не пишет
python3 syntax_fix/fix_syntax.py /tmp/x/out/sources --apply  # применить
python3 syntax_fix/verify.py                                 # пересчёт: 13384 / 8
```

Скрипт не зависит от прав доступа и не трогает файлы, которые уже валидны:
он ищет только те, что не парсятся, и для каждого пробует правила по очереди
до первого успеха.

## Важная оговорка

Синтаксическая валидность ≠ компилируемость. По-прежнему:
* **4 475** файлов требуют Android SDK (заблокирован в песочнице);
* **547** native-методов, из них **136** без парного экспорта в `.so`;
* движка `libroblox.so` в сборке нет (`nativeStart` отсутствует).

То есть эти 74 правки — про **читаемость и структурную целостность дампа**, а не
про работающее приложение. См. `COMPILE_PLAN.md` и `compile_audit/README.md`.
