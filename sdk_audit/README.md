# SDK скачан. Что изменилось

Просьба была «скачай SDK» — скачал. И это дало самый точный результат из всех
проверок до сих пор.

## 1. Что удалось достать, а что нет

Проверил 10 источников. Открыты только `codeload.github.com`, `api.github.com`,
`pypi.org`, `files.pythonhosted.org`.

| что | источник | результат |
|---|---|---|
| **`android.jar` (API 35)** | `codeload.github.com/Sable/android-platforms` | ✅ **скачан**: 26 МБ, **5 981 класс**, `android/content/Context`, `android/os/Parcel` на месте |
| JDK с GitHub Releases | `github.com/…/releases` | ❌ release-ассеты блокированы (TLS EOF) |
| JDK через `install-jdk` (PyPI) | Adoptium/API | ❌ тот же блок при скачивании |
| `jdk4py` (PyPI) | PyPI | ✅ скачался, но это **JRE**: `jdk.compiler` нет |
| ECJ (компилятор) | maven central / apache / aliyun | ❌ все три блокированы |
| ECJ из GitHub-репозиториев | codeload | ❌ в доступных репо только `gradle-wrapper.jar` (48 КБ) |
| `dl.google.com` (официальный SDK) | Google | ❌ блокирован |

**Итог: SDK-часть (android.jar) есть, компилятора нет.** Поэтому вместо сборки —
проверка контракта с реальным API, что даёт более полезный ответ.

## 2. Главный результат: код соответствует API

Сверил **все** импорты в дампе с фактическим содержимым `android.jar` API 35 —
того самого уровня, на который собран APK (`targetSdk 35`).

| категория импортов | импортов | не найдено |
|---|---|---|
| `android.*` (framework) | **14 485** | **281 (1.9%)** |
| `androidx.*` (библиотеки) | 2 569 | 0 ✅ |
| `com.google.android.*` | 1 197 | 0 ✅ |

**Файлов с полностью разрешимым framework-контрактом: 13 232 из 13 392 (98%).**
Потеряно всего 160 файлов (1%) — и это важно: до скачивания SDK я оценивал
«4 475 файлов требуют Android SDK». Проверка показала, что **эта оценка была
пессимистичной в 28 раз**: SDK закрывает почти всё, кроме 1%.

## 3. Что именно потеряно (26 уникальных классов)

Все 281 потерянных импорта — это **26 имён**, и почти все из `android.view`:

| класс | файлов | что это |
|---|---|---|
| `android.view.l`, `l0`, `s`, `a1`, `x0`, `f`, `t`, `d0`, `b1`, `c1`, `r`, `h0`, `p`, `f0`, `e0`, `k0`, `j0`, `a0`, `d`, `y`, `z0`, `y0`, `u`, `b0` | 160 | **внутренние классы Android framework** — JADX вытащил ссылки на непубличные `android.view.*` |
| `android.view.C0795e1` | 3 | имя с dex-суффиксом |
| `android.view.ProcessLifecycleInitializer` | 1 | JADX перепутал пакет (реально `androidx.lifecycle`) |

Ни одного класса из `android.app`, `android.os`, `android.content`,
`android.graphics`, `android.net`, `android.util` — **эти пакеты разрешились
полностью**. То есть вся прикладная часть дампа опирается на публичный API.

## 4. Почему компиляция всё ещё не запускается

Даже с `android.jar` не хватает трёх вещей, и все три — вне SDK:

1. **Компилятор.** `javac` требует `jdk.compiler`; в скачанном JRE его нет,
   ECJ скачать нечем. Это единственная оставшаяся «инфраструктурная» дыра.
2. **`androidx.*` и `com.google.android.*` в виде jar.** Проверка показала, что
   имена из этих пакетов **есть в `android.jar`** (это заглушки публичного API),
   но реальная реализация — в отдельных AAR. Для проверки компилируемости
   заглушек достаточно, для запуска — нет.
3. **`R` и `BuildConfig`** — уже восстановлены (`R_recovered/`).

То есть барьер теперь чисто механический: нужен любой компилятор Java 8+
уровня. На машине с JDK это одна команда.

## 5. Как проверить самому (на машине с JDK)

```bash
# android.jar уже в репозитории? нет — скачать так:
curl -L -o android.jar https://codeload.github.com/Sable/android-platforms/tar.gz/refs/heads/master
tar -xzf android.jar --wildcards '*/android-35/android.jar'

# скомпилировать весь дамп
cd 02_sources/java
find . -name '*.java' > /tmp/sources.txt
javac -nowarn -proc:none -d /tmp/out \
      -cp /tmp/android35.jar \
      -sourcepath . @/tmp/sources.txt 2> /tmp/errors.txt

# сколько файлов реально упало
grep -c '^\./.*error:' /tmp/errors.txt
grep 'error:' /tmp/errors.txt | sed 's/.*error: //' | sort | uniq -c | sort -rn | head
```

Прогноз по этому аудиту: основная масса ошибок будет не в коде Roblox, а в
`androidx`/`kotlin` (реализации нет, только заглушки) и в 160 файлах с
внутренними `android.view.*`. Прикладной код должен пройти.
