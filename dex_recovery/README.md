# Восстановление из DEX: главная находка

Ты спросил «что лучше — делай». Я выбрал **DEX**, а не эвристики по сурсам, и
это оказалось правильным: DEX дал точный ответ на вопрос, почему javac выдал
28 611 ошибок, и этот ответ опроверг мою же предыдущую гипотезу.

## Что выяснилось (по порядку)

### 1. `R` — не причина. Проверено по DEX.

Я проверил `R`-классы по всем четырём dex. **`Lcom/roblox/client/R;` в DEX
нет вообще** — R8 удалил его и встроил числовые значения прямо в код
(`const v0, 0x7f0403b7`). Значит `R` не может быть источником 28 611 ошибок.
Заодно выяснилось, что восстановленный `R_recovered/R.java` **совпадает** с
`personasdk/R.java` по всем проверенным атрибутам (`actionBarDivider`,
`toolbarStyle`, `windowNoTitle`) — то есть и по этим ссылкам всё в порядке.

Вывод: 348 замен из правила F3 остаются полезными, но они не решают проблему.

### 2. Настоящая причина: пропавшие ВЛОЖЕННЫЕ классы

Беру худший файл, `ci/a.java` (409 ошибок). В нём 408 полей вида:

```java
public final a.b A;
public final a.C0143a A0;
public final a.d A2;
```

Классов `a.b`, `a.C0143a`, `a.d` в файле **нет**. Открываю DEX — и там
однозначно:

```
поле A  класса Lci/a;  :  Lcom/roblox/client/flags/a$b;
поле A2 класса Lci/a;  :  Lcom/roblox/client/flags/a$d;
```

То есть `a` в этих типах — это `com.roblox.client.flags.a`, **другой класс с
тем же коротким именем**, а не `ci.a`. JADX сгенерировал самоссылку: тип
написал коротко (как он был в dex-е), а импорт `com.roblox.client.flags.a`
превратил его в `a.d`, то есть `ci.a.d`, которого не существует.

### 3. Мой первый генератор был сломан — и это видно по коду

Я написал генератор заглушек и вставил 8 435 вложенных классов в 945 файлов.
Проверка парсером показала **59 ошибок** — и хорошо, что я её сделал:

| дефект | было | причина |
|---|---|---|
| имя класса с `$` | `class a$a` | брал путь целиком, а не последний сегмент |
| конструктор с `$` | `public a$a(...)` | то же, но в теле |
| синтетические имена | `class 1` | Kotlin-классы вида `Foo$resultReceiver$1` в Java невыразимы |

После трёх исправлений: **887 из 909 файлов валидны (97,6%)**, имён с `$` — 0.

Оставшиеся 22 — это 1% дампа, который был сломан **изначально** (см. п.4).

### 4. `??` — и моя ошибка в его оценке

**Важная поправка.** Я утверждал, что 36 файлов сломаны из-за `??`. Проверил:
правило R7 (из первого раунда починки) **уже** заменяло `??` на `var`, и для
`javac` это работало. Ложную тревогу дал мой же инструмент проверки:
**`javalang` не понимает `var`** и помечал такие файлы сломанными.

То есть из 52 «сломанных» файлов 36 на самом деле компилируются. Реальное
число — около **16**, и это меняет оценку дампа в лучшую сторону.

`fix_unknown_local.py` остаётся полезным только для `?? x;` без
инициализатора — там `var` запрещён даже в Java 10+.

### 4a. Правило F4: `?? name = ...` — потерянный тип локальной переменной

36 файлов содержали `??` там, где JADX не вывел тип регистра:

```java
?? mediaMuxer = new MediaMuxer(e10.getAbsolutePath(), 0);
```

Тип берётся из правой части: `new X(` → `X`, приведение → тип, литерал → тип
литерала, иначе `Object`. Из 34 объявлений 16 получили точный тип, 18 — `Object`
(компилируется, но обращение к полям такого объекта может не найтись).

**Результат: 52 файла помечает сломанными `javalang`, но ~36 из них валидны
для javac** (используют `var`). Реально сломаны около 16.

## Чего ждать от следующей сборки — честно

Вложенные классы восстановлены **по сигнатурам**, тела — заглушки
(`throw new UnsupportedOperationException`). Поэтому:

* ошибки `cannot find symbol: class a.d` должны уйти;
* появятся другие: код вызывает `a.d.someMethod()` там, где в настоящем
  классе сигнатура другая. Это неизбежно, пока тело — заглушка.

Точную цифру не назову. Но структура теперь верная: раньше компилятор не
видел типов вообще, теперь видит, пусть и с заглушками.

## Запуск

```bash
git pull
bash build_kit/build.sh
python3 build_kit/analyze_errors.py build_kit/errors.txt
```

Скрипт сам: скачает `android.jar` → распакует дамп → наложит 157 правок →
**прогонит DEX-восстановление** → исключит 9 невосстановимых → скомпилирует.

## Что это меняет в оценке дампа

До этого раунда я считал, что дамп «валиден на 99,94%». Это было верно только
для синтаксиса. **По типам дамп потерял 8 899 вложенных классов (32% всех
типов)** — вот настоящая цена декомпиляции, и её не было видно ни в одном
статическом отчёте. Видно стало только когда появился DEX-эталон для сверки.

Именно поэтому DEX — правильный путь, а не эвристики: он единственный даёт
**эталон**, с которым можно сверять. Без него любая «починка» — угадывание.
