# Аудит компилируемости: что реально можно собрать

Задача была: «взять JDK, собрать JDK-only срез, показать настоящие ошибки
компиляции». Раздел «что не получилось и почему» честно первый.

## 1. Компилятора получить не удалось (все пути проверены)

| попытка | результат |
|---|---|
| `java` / `javac` / `gradle` в системе | отсутствуют |
| `curl` JDK с GitHub Releases (184 МБ) | `SSL_ERROR_SYSCALL` — release-ассеты заблокированы |
| то же через `urllib`, 3 попытки | `TLS/SSL connection has been closed` |
| `pip install jdk4py` | **сработало**, JDK 25.0.5.1 скачан |
| `jdk4py/java-runtime/bin/javac` | **нет** — это JRE, только `java`, `keytool`, `jfr` |
| `java --list-modules` | 36 модулей, **`jdk.compiler` отсутствует** |
| `java Probe.java` (source launcher) | `InternalError: Module jdk.compiler not in boot Layer` |
| `repo1.maven.org` (ECJ-компилятор) | заблокирован |
| `pip install ecj` | пакета нет |

Вывод: в этом окружении **скомпилировать Java физически нечем**. Поэтому ниже —
статический аудит, который даёт те же ответы там, где они не требуют кодогенерации.

## 2. Что измерено (13 392 файла)

### Разбор синтаксиса

| метрика | значение |
|---|---|
| файлов всего | 13 392 |
| разобрано javalang | **13 310 (99.4%)** |
| синтаксически сломано | **82 (0.6%)** |

Причина сломанных — не «придирки парсера», а реальные ошибки JADX: например
`public final T default;` в `deobf/com/roblox/client/l6/Extras.java:29` —
`default` это ключевое слово Java, такой файл не скомпилирует **ни один**
компилятор. Второй класс проблем — невосстановленные enum
(`JADX WARN: Failed to restore enum class`) в `pushnotification/lg/*`.

### Разрешимость импортов

| метрика | значение |
|---|---|
| импорты полностью разрешимы | **8 835 (66%)** |
| есть неразрешимые импорты | **4 475** |

Неразрешимые — это **внешние библиотеки**, которых нет в дампе, и почти всё это
Android framework: `android.content.Context` (1 402), `android.os.Parcel` (925),
`Parcelable` (829), `Bundle` (524), `res` (387), `Build` (385). То есть 4 475
файлов требуют `android.jar` — но `android.jar` нельзя просто скачать и
поставить, нужен Android SDK (заблокирован), и даже с ним это лишь заглушки
API без реализации.

### Символьная целостность (внутри дампа)

Индекс собран по **вложенным** классам тоже: **117 138 FQN** в 1 182 пакетах,
из них 52 213 типов имеют объявленные члены (методы, поля, конструкторы).

| метрика | значение |
|---|---|
| проверено обращений `Класс.член` по классам дампа | 19 534 |
| член найден | **19 126 (97.9%)** |
| член НЕ найден | 408 (2.1%), 101 уникальная пара |

Потерянные члены — это не «сломанный код», а следствие того, что часть Kotlin
top-level функций после декомпиляции попала в другой holder-класс
(`CollectionsKt.firstOrNull`, `StringsKt.p0`) и что enum-константы
(`TelemetryBackend.COUNTER`) не восстановлены как поля. То есть код внутренне
**согласован на 97.9%** — это неожиданно хороший результат для обфусцированного
дампа.

### Жёсткие проверки структуры

| проверка | нарушений |
|---|---|
| `public`-класс не совпадает с именем файла | **0** |
| несколько `public`-классов в файле | **0** |
| дублирующиеся FQN | **0** |

## 3. Что из этого следует

**Собираемость дампа не упирается в качество кода.** Цифры говорят: код в
основном валиден (99.4% парсится, 97.9% символов сходится, 0 структурных
нарушений). Упирается всё в два внешних условия:

1. **4 475 файлов требуют Android SDK** — его нет и взять неоткуда.
2. **Движок `libroblox.so` невосстановим** — `nativeStart` отсутствует, 136 из
   547 native-методов без парного экспорта (см. `COMPILE_PLAN.md`).

То есть **даже с компилятором** полная сборка дала бы: 82 файла с гарантированной
ошибкой синтаксиса + 4 475 файлов без зависимостей + APK, который не запустится.

## 4. Что действительно можно собрать

**8 835 файлов с разрешимыми импортами** — верхняя граница. Из них файлы,
которые не тянут Android, компилируются обычным `javac` с JDK (у нас его нет, но
на любой машине с JDK это одна команда):

```bash
# на машине с JDK 17+
find 02_sources/java -name '*.java' > sources.txt
javac -d /tmp/out -sourcepath 02_sources/java @sources.txt 2>errors.txt
wc -l errors.txt          # реальное число ошибок
```

Ожидание по аудиту: основная масса ошибок будет «package android.* does not
exist» и «cannot find symbol» для Kotlin-холдеров — то есть ровно те 4 475 + 101
уникальная пара, что найдены здесь статически.

## 5. Файлы аудита

| файл | что делает |
|---|---|
| `build_index2.py` | индекс всех FQN, включая вложенные классы (117 138) |
| `analyze.py` | разрешимость импортов по файлам → `clean_imports.json` |
| `final.py` | проверка `Класс.член` по 52 213 типам с членами |
| `hard_errors.py` | имя файла vs класс, дубли FQN, `public`-нарушения |
| `clean_imports.json` | список 8 835 файлов с разрешимыми импортами |

Скрипты воспроизводимы: кладут дамп в `/tmp/x/02_sources`, запускаются по
порядку. Время полного прогона — около 4 минут.
