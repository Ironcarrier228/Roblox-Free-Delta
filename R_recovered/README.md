# Восстановление `R.java` из таблицы ресурсов

`R.java` для `com.roblox.client` восстановлен из `resources.arsc`, обфусцированные
стабы расшифрованы, обращения в коде переименованы.

## Что получилось

| файл | что это |
|---|---|
| `R.java` | 6 191 ресурс основного пакета (`0x7f…`), 19 типов, компилируемый |
| `R_aliases.java` | 614 записи второго пакета (`0x87…`), отдельно |
| `rename_map.tsv` | 312 строк: стаб-поле → имя ресурса → id → корректная ссылка |
| `apply_rename.py` | переименование обращений в дампе (416 замен) |

## Расшифровка стабов

`R` был разбит на 10 классов, каждый — ровно один тип ресурса:

| класс | тип | полей |
|---|---|---|
| `bh/i0` | bool | 1 |
| `bh/j0` | color | 15 |
| `bh/k0` | dimen | 6 |
| `bh/l0` | drawable | 28 |
| `bh/m0` | id | 76 |
| `bh/n0` | layout | 32 |
| `bh/o0` | menu | 4 |
| `bh/p0` | mipmap | 2 |
| `bh/q0` | string | 145 |
| `bh/r0` | style | 3 |

**312 из 312 полей сматчились по id без единого промаха.** Это доказывает, что
соответствие восстановлено точно, а не угадано. Пример:

```
deobf/com/roblox/client/provider/ph/b.java
    public static int f29162a = 2131886615;
    → 0x7f120217 → string/shell_configuration_provider_authority_suffix
    → R.String.shell_configuration_provider_authority_suffix
```

Это ровно то поле, которое задаёт authority провайдера в `DEEP_PROVIDER.md`.

## Осторожно: имена стабов — ещё и имена переменных

`r0`, `n0`, `l0` массово используются как локальные переменные. Поэтому правило
замены жёсткое: не после точки, поле обязано быть в стабе, не вызов метода.

Итог: **416 точных попаданий**, **4 451 кандидат отсеян** — в основном
`r0.append`, `l0.class`, `j0.WaitForAutocapture` и регистры из
байткод-листингов. Скрипт запускать только на копии дампа.

## Две ловушки в таблице

1. **Дубли по локалям.** 23 925 записей → 6 805 уникальных id: одна строка
   повторяется для каждой конфигурации (`zh-rTW`, `zu`, …).
2. **Два пакета ресурсов.** 614 записей имеют id `0x87…`, причём **с другими
   числами при тех же именах** (`id/content` = `0x7f0900a6` и `0x8705003e`).
   Если свести всё в один `R`, будет 12 пар с одинаковым именем и разными
   значениями. Поэтому алиасы вынесены в `R_aliases`.

## Ограничения

* 1 229 имён не являются Java-идентификаторами (`$avd_hide_password__0`,
  `Theme.AppCompat` с точками) — санитайзятся в `_`;
* имена полей (`f29162a`, `O1`) не оригинальные, но привязка к ресурсу точная;
* собираемым дамп от этого не станет — см. `BUILD_FEASIBILITY.md`.

## Что проверено

| проверка | результат |
|---|---|
| баланс скобок в `R.java` | 20 / 20 |
| дубли имён внутри типа | 0 |
| уникальных id | 6 191 из 6 191 |
| сверка `rename_map.tsv` ↔ `R.java` | 312 / 312, 0 расхождений |
| прогон на копии дампа | 74 файла, 416 замен |
| `q0.O1` после прогона | 0 вхождений |
| локальные переменные (`r0.append`, `l0.class`) | не тронуты |

Осталось **1 670** обращений к стабам, которые скрипт намеренно не трогает:
это либо вызовы методов (`r0.add(...)`), либо обращения из других классов-стабов,
где имя поля неоднозначно. Их надо разбирать вручную по `rename_map.tsv`.

